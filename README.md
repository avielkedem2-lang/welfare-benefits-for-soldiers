"# welfare-benefits-for-soldiers" 


מבנה קבצים:




כל האנדפויטים:


1. POST/soldiers/:soldierId/benefits => האנדפויט הזה מקבל אובייקט ןהמערכת בודקת אם הכל תקין במידה וכן המערכת מכניסה db ומחזירה למשתמש status 201 ומחזירה רשומת הטבה.
במידה ולא הכל היה תקין למשל כבר קיימית רשומת הטבה עם אותו id המערכת מחזירה למשתמש status 409 
ואומרת לו שכבר קיים כזאת רשומה.


2. GET/soldiers/:soldierId/benefits => מקבלת soldierId אם קיים מחזירה status200 והרשמה מלאה כולל הסטוריה,
אם לא אז מחזיר status 400



3. PATCH/soldiers/:soldierId/benefits => מקבלת אובייקט ו id של חייל ואם החייל קיים והכל תקין המערכת מחזירה status 200 ורשומה מלאה.
במקרה ויש בעיה מחזיר status 400


4. POST/budget => מקבלת אובייקט אם תקין והכל בסדר מחזיר status 201 והקצה חדשה.
במקרה ולא תקין status 400 



5. GET/ budget => מקבלת query אם תקין והכל טוב מחזיר רשימה של כל הquety שהוא הכניס


6. GET/budget/:id/transaction => מקבלת id ומחזירה את כל העסקאות שעל הקצאה הזו
עם status 200
במקרה שלא נמצא מחזירה status 404.


7. POST/budget/:id/spend => מקבלת אובייקט ומחזירה status 201 ואת עסקת הניצול שנוצרה,
במקרה של דחייה היא מחזירה אובייקט עם סיבה שלגיאה וכמות שנשאר.





הסבר לבחירת בסיס נתונים לכל ישות:

1. welfare_record => אני בחרתי בבסיס נתונים של mongodb כי זה לא רלציוני ועם לא רלציונני אנחנו מתעסקים עם אובייקטים ורשימות


2. budget_allocation => אני בחרתי בבסיס נתונים של spuabase מכיוון שזה רלציוני,
ובגלל הקישור של furnkey.



3. spend_transaction => אני בחרתי בבסיס מבנה נתונים של supabase כי זה רלציוני,
ובגלל הקישור של furnkey.
